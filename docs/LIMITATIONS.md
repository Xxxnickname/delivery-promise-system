# 当前边界与路线图

## 1. 已经具备

- 11 屏静态前端：登录、驾驶舱、订单查询/详情、缺料台账/追溯、库存/退货、模拟、导入、快照、基础数据、用户管理；
- 四表 CSV 模板、导入、行列级校验、全或无/部分导入、幂等；
- 5 层 BOM 展开、环检测、超层报错、损耗、多路径；
- 库存 + 在途供给冲减、齐套日、最早开工日、交期承诺、缺口影响；
- 插单/加急模拟、快照对比、xlsx 导出；
- JWT 登录、PBKDF2 密码哈希、演示用户种子、SQLite 持久化；
- DeepSeek/OpenAI-compatible 表头映射建议与规则回退；
- 33 条 pytest、22 条边界场景、20 单替身基准。

## 2. 当前限制

| 项 | 当前状态 | 影响 |
|---|---|---|
| 前端真实数据 | 仍使用 `static/mock` | 页面不能直接展示后端真实导入结果 |
| 前端登录 | 静态 mock 任意非空密码 | 与后端 `demo123` 行为不同 |
| 客户范围 | 前端 mock 过滤；后端未强制 | 生产前必须补订单查询过滤 |
| 角色权限 | 前端菜单控制；后端仅导入/模板/BOM 限制 | 生产模式其他接口对已登录用户开放；开发模式可无 token |
| 租户隔离 | `X-Tenant-Id` 可指定，未与 JWT 强绑定 | 不能视为生产级隔离 |
| 采购角色 | 无独立账号 | 主管导出缺口表线下交采购，计划员回填到货 |
| 缺料台账 | 页面 mock；后端无独立 shortage API | 真实缺料需从订单承诺 `gaps` 聚合 |
| 库存/退货 | 页面 mock；后端库存只参与计算 | 退货未建模，成品/原材料未分表 |
| 基础数据 | 页面 mock；别名队列在内存 | 无持久化 CRUD |
| 用户管理 | 页面 mock；后端无 CRUD API | 只能通过种子/数据库维护用户 |
| 替代料 | 服务与单测已实现 | 未接入订单承诺主链路 |
| 审计 | 表结构与 `audit()` 已建 | 业务路径未调用，未落库 |
| 导出 | web 进程线程池 | Celery 导出任务未启用；登录后任务归属取 JWT，未登录开发模式回退 `X-User-Id` |
| PostgreSQL | 迁移已准备 | 容器未在本机实际启动验证 |
| Redis/Celery | 骨架与 ping 任务 | 未做生产队列/重试/死信验证 |
| 20 单基准 | synthetic stand-in | 不是人工核算真值 |
| 可观测性 | `trace_id` + 统一错误 | 无正式 metrics/alerts |
| 前端图表 | 内联 SVG + mock | 没有真实数据联调 |

## 3. 角色与采购协同边界

本期没有采购登录账号。推荐流程：

1. 主管在缺料台账查看高风险物料和受影响订单；
2. 导出缺口表（后端 `kit_report` 或页面 mock 导出）；
3. 线下交采购催料/询价；
4. 采购反馈到货日期和数量；
5. 计划员把到货批次写入 `in_transit.csv`；
6. 到货后更新 `inventory.csv` 的 `on_hand`；
7. 重新导入并复算；
8. 销售查看最新承诺。

后续可扩展：

- 采购账号与供应商范围；
- 询价单/采购单；
- 到货质检、退货入库；
- 供应商交期确认与异常提醒；
- 采购与缺口的自动关联。

## 4. 推荐路线图

1. **前端接真实 API**：把 `MOCK=true` 切到适配层，完成登录、导入、订单、缺料、模拟、快照、导出联调；
2. **权限与租户**：客户范围过滤、JWT 租户绑定、用户 CRUD、审计落库；
3. **PostgreSQL 实跑**：执行迁移、重启恢复、索引与慢查询；
4. **Redis/Celery**：导出/计算异步化、重试、死信、任务观测；
5. **替代料主链路**：替代组、替代库存、审批策略接入；
6. **真实基准**：用人工核算的 20 单替换 synthetic stand-in；
7. **生产部署**：Nginx/TLS、多 worker、备份/回滚、监控告警；
8. **压测与安全**：20 并发、故障注入、权限审计、密钥轮换；
9. **采购协同**：采购账号、询价、到货、退货质检。

- `docs/`、截图、README、LICENSE、SECURITY、CONTRIBUTING
- `.github/`、Dockerfile、compose、requirements
